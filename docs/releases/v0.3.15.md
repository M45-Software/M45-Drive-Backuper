# v0.3.15 — Backup checks, file recovery, and flexible run controls

This preview adds the following features since v0.3.7.

- **Integrity checks:** manually check the most recent completed snapshot (default), a selected snapshot, or the whole repository. Optional after-backup, daily, weekly, and monthly checks remain opt-in; manual-only is the default. Snapshot checks read and validate that snapshot’s recovery data; whole-repository checks use Borg’s full data verification.
- **Browse and recover:** browse saved snapshots and recover selected files or folders into a fresh user-owned subfolder under `~/Recovered Files` by default, with a destination chooser. Recovery preserves existing files and reports incomplete results.
- **Run controls:** pause/resume or cancel backups and checks from the tray and main window. Postpone a current or new run for 1, 4, or 24 hours, or pause future runs without changing saved schedules. Paused jobs retain their repository lock; keep their drives connected.
- **Reminders:** opt into daily, weekly, or 30-day reminders for manual backups and checks, with one-day snoozing. Reminders are off by default, do not start jobs, and reset after successful runs.
- **Idle waiting:** separately opt automatic backups and checks into waiting until user sessions report idle for 10 minutes. The maximum delay defaults to 6 hours, with 12-, 24-, and 48-hour choices. Repeated triggers never extend a pending deadline; jobs start at the deadline even if the system remains busy. Manual runs and explicit postponements bypass idle waits.
- **Unavailable idle reporting:** disable idle waiting and grey out its controls with an explanation; release already-waiting jobs instead of holding them. Normal schedules continue.
- **Tray and theme:** show distinct animated backup, check, and recovery activity, with a clear paused state. Simplify navigation and make dropdowns, disabled controls, placeholder text, tables, and recovery dialogs follow the desktop palette, including live light/dark switches.

Existing backup and verification settings are preserved. New optional features remain off until enabled. Postponements and idle waits continue with the monitor closed; desktop reminders require the tray monitor and permitted notifications.

Validated with the Qt UI suite, Python backend tests, real Borg backup/recovery harness, light/dark previews, and disposable systemd-service tests for parent/child pause, cancellation, postponement, and idle-wait release paths. The disposable-service tests do not operate on user backup repositories.
